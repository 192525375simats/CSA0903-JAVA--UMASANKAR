## How to compile and run (inside each folder)
```
javac -d out <files>.java          # e.g. Q1: javac -d out TicketBench.java
java -cp out <MainClass>            # e.g. java -Xms1g -Xmx3g -cp out TicketBench
```
Exact commands used for every screenshot are printed on the first line of each `output*.svg`/`.txt` header. Q3: run inside `Q3/before` and `Q3/after` for the two `Attendance` runs, and in `Q3` for `ContractTests`. ## Notes on measurements
- Times are averages/medians/minimums of repeated runs after warm-up (stated in each `ANALYSIS.md`); allocation is measured with `ThreadMXBean.getCurrentThreadAllocatedBytes`; operation/char-copy counts are reported where relevant. Absolute numbers depend on the machine (a 2-core cloud Linux container); ratios and growth rates are the evidence.
- Output screenshots are SVG terminal renderings generated by `tools/render_svg.py`, which runs the command and renders its real stdout – the matching `.txt` file next to each is the raw output.
- Honest corrections are recorded where predictions were wrong (e.g. Q1: StringBuffer was not measurably slower single-threaded; Q6: the first starvation experiment used an empty queue and was uninformative, so it was re-designed with a backlog).
